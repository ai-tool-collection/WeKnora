WeKnora 企業內網架設安裝指南

以台灣正體中文說明：在專用 Ubuntu 24.04 LTS 主機上，以 Docker Compose 部署 WeKnora、ParadeDB、Redis 與 Docreader，透過企業內網 HTTPS 提供服務，並將文件與問答留在公司核准的資料流內。

原始碼：8619bdf3c5149acc8ca51263e4d485f97da39211單機 Compose不啟用選用 profile需內部模型服務

先看部署範圍與前提

這份手冊選擇一條可重現的路徑：使用目前已審查的 commit 自行建置三個 WeKnora 映像，使用 Compose 啟動五個核心服務，再由主機 Nginx 提供內網 HTTPS。正式機須先完成映像掃描與網路出站管制，才可匯入機密文件。

版本差異：此 commit 的 VERSION 為 0.8.2，但位於 v0.8.2 Git 標籤之後 24 個提交。直接拉取 wechatopenai/weknora-*:v0.8.2 無法證明與本指南及前份資安報告檢查的程式相同。本指南用 internal-8619bdf 作為自行建置的映像標籤。

1準備專用主機、DNS 與網路

先由網路／系統管理員建立主機與內網 DNS。初次註冊期間，僅允許管理員 IP 連到 443；正式上線後再放行員工網段。SSH 只允許管理網段。ParadeDB 5432、Redis 6379、Docreader 50051 不需對外開放。

uname -m
lsb_release -ds
free -h
df -h /
getent hosts kb.corp.example

將範例 FQDN 改成公司真實名稱。向模型平台取得端點，例如 http://ollama.corp.internal:11434；此端點只應允許 WeKnora 主機來源連線。正式環境建議在模型服務前放置 TLS 代理並讓容器信任其 CA。

過關條件：主機資源足夠、DNS 解析正確、企業憑證已核發、模型端點與網路 ACL 已確定。

2安裝 Docker Engine 與 Compose Plugin

下列命令適用於乾淨的 Ubuntu 24.04。已有公司核准 Docker 套件者，可跳過安裝，直接驗證版本。Docker 群組等同具備高度主機權限；本手冊使用 sudo docker，不把一般使用者加入 docker 群組。

sudo apt update
sudo apt install -y ca-certificates curl git python3 nginx
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker version
sudo docker compose version

本指南的 !override 語法要求 Docker Compose 2.24.4 以上。若版本不足，先更新 Plugin；不可略過步驟 5 的連接埠檢查。

Docker 發布的容器連接埠可能繞過主機 ufw 規則。企業網路 ACL 與步驟 5 的 loopback 綁定是必要控制，不能只看 ufw status。見 Docker 官方 Ubuntu 安裝說明與防火牆說明。

4建立一次性的環境設定與金鑰

先將模型服務 URL 改成公司實際端點，再執行下列指令。程式會從 .env.example 建立 .env，為資料庫、Redis、JWT、AES 與簽章產生隨機值；若 .env 已存在，會中止以避免重新產生金鑰。SYSTEM_AES_KEY 為 32 個 ASCII 字元，日後必須與備份一起保管。

cd /srv/weknora/source
export WEKNORA_MODEL_URL='http://ollama.corp.internal:11434'  # 改成真實內部端點
umask 077
python3 - <<'PY'
from pathlib import Path
from urllib.parse import urlparse
import os, re, secrets

target = Path('.env')
if target.exists():
    raise SystemExit('.env 已存在：停止，避免覆寫正式環境金鑰')
url = os.environ.get('WEKNORA_MODEL_URL', '').rstrip('/')
parsed = urlparse(url)
if parsed.scheme not in ('http', 'https') or not parsed.hostname or parsed.hostname.endswith('.example'):
    raise SystemExit('請先設定真實的 WEKNORA_MODEL_URL')
content = Path('.env.example').read_text(encoding='utf-8')
def put(name, value):
    global content
    row = f'{name}={value}'
    pattern = rf'(?m)^{re.escape(name)}=.*$'
    content, count = re.subn(pattern, lambda _: row, content)
    if not count:
        content += '\n' + row + '\n'

values = {
    'WEKNORA_VERSION': 'internal-8619bdf',
    'APK_MIRROR_ARG': '',
    'GIN_MODE': 'release',
    'LOG_LEVEL': 'warn',
    'LLM_DEBUG_LOG': 'false',
    'TZ': 'Asia/Taipei',
    'WEKNORA_LANGUAGE': 'zh-TW',
    'DEFAULT_LOCALE': 'en-US',
    'FRONTEND_PORT': '8088',
    'APP_PORT': '8080',
    'DB_PASSWORD': secrets.token_hex(24),
    'REDIS_PASSWORD': secrets.token_hex(24),
    'JWT_SECRET': secrets.token_hex(32),
    'SYSTEM_AES_KEY': secrets.token_hex(16),
    'SYSTEM_SIGNING_KEY': secrets.token_hex(32),
    'STORAGE_TYPE': 'local',
    'RESOURCE_URL_MODE': 'handle',
    'OLLAMA_BASE_URL': url,
    'OLLAMA_OPTIONAL': 'true',
    'SSRF_WHITELIST': parsed.hostname,
    'SSRF_DNS_WHITELIST_ONLY': 'true',
    'DISABLE_REGISTRATION': 'false',
    'WEKNORA_AUTH_COMPLEX_PASSWORD_ENABLED': 'true',
    'WEKNORA_SANDBOX_DOCKER_ENABLED': 'false',
    'LANGFUSE_ENABLED': 'false',
    'LANGFUSE_PUBLIC_KEY': '',
    'LANGFUSE_SECRET_KEY': '',
}
for name, value in values.items():
    put(name, value)
target.write_text(content, encoding='utf-8')
target.chmod(0o600)
print('.env 已建立；金鑰未顯示。請立即納入公司機密管理與加密備份。')
PY
stat -c '%a %n' .env
git status --short
請勿執行 cat .env、提交 .env 或把 sudo docker compose config 的完整輸出貼到工單。它們會洩漏密碼。遺失 SYSTEM_AES_KEY，已加密的憑證將無法還原。.env 是設定，不是金鑰保管庫；正式環境應備份至公司加密秘密管理系統。

為何清空 APK_MIRROR_ARG：.env.example 原本填入 mirrors.tencent.com；名稱和註解雖寫 APK，實際上 app 的 Dockerfile 會用它替換 Debian APT 來源主機。留空即可沿用基底映像的預設 Debian 來源；它不是 WeKnora 執行時必需的設定，也不控制 Docreader（後者另用 APT_MIRROR）。如果之前已用騰訊鏡像建置 app，改空值後須重新建置；想排除舊建置快取，使用 build --no-cache app。若使用預先建好的映像，改此值不會變更該映像已安裝的套件。

WeKnora 前端目前沒有 zh-TW 語系；本指南將介面預設為英文，提示詞回退語言為 zh-TW。若要台灣正體中文 UI，須另外完成前端在地化。

5覆寫對外連接埠並驗證

原本的 Compose 將 80、8080 發布到所有主機介面。建立一份專用覆寫檔，!override 會取代原有 ports 清單，避免同時留下公開埠。此檔可維護於內部部署版本庫。

cd /srv/weknora/source
cat > compose.internal.yml <<'YAML'
services:
  frontend:
    ports: !override
      - "127.0.0.1:${FRONTEND_PORT:-8088}:80"
  app:
    ports: !override
      - "127.0.0.1:${APP_PORT:-8080}:8080"
YAML
sudo docker compose -f docker-compose.yml -f compose.internal.yml config -q
sudo docker compose -f docker-compose.yml -f compose.internal.yml config --format json | python3 -c '
import json,sys
s=json.load(sys.stdin)["services"]
for name in ("frontend","app"):
    p=s[name].get("ports",[])
    assert len(p)==1 and p[0].get("host_ip")=="127.0.0.1", (name,p)
    print(name, p[0]["host_ip"], p[0]["published"], "->", p[0]["target"])
for name in ("postgres","redis","docreader"):
    assert not s[name].get("ports"), name
print("連接埠檢查通過")'

注意：往後所有 Compose 命令都需同時帶 -f docker-compose.yml -f compose.internal.yml。不能只執行預設的 docker compose up，否則會回到原本的公開連接埠。Docker 官方文件確認 !override 需 Compose 2.24.4 以上。

過關條件：輸出只顯示 frontend 127.0.0.1:8088、app 127.0.0.1:8080；另外三個核心服務沒有 ports。

6取得基礎映像、建置並檢查 WeKnora 映像

在沒有業務文件與公司密碼資料的建置環境執行。建置階段會從套件庫與上游取得基底映像、Go／Python／npm／Rust 相依套件，以及 BrowserSkill 來源；應使用公司核准的建置網路、掃描產物與供應鏈審查。下列命令會從已固定的原始碼建置三個 WeKnora 服務，不拉取同名的官方 release 映像。

cd /srv/weknora/source
sudo docker compose -f docker-compose.yml -f compose.internal.yml pull postgres redis
sudo docker compose -f docker-compose.yml -f compose.internal.yml build --pull app docreader frontend
sudo docker image inspect \
  wechatopenai/weknora-app:internal-8619bdf \
  wechatopenai/weknora-docreader:internal-8619bdf \
  wechatopenai/weknora-ui:internal-8619bdf \
  --format '{{.RepoTags}} {{.Id}}'

建置完成後，請對這五個映像做公司既有的漏洞掃描、SBOM 與許可證審查，記錄映像 digest；正式環境最好將同一批核准映像移至內部 registry。自行建置只解決「使用哪份原始碼」的可追溯性，不能取代相依套件和建置階段對外請求的審查。

過關條件：三個自建映像存在、建置無錯、基礎映像與產物符合公司核准政策。

7設定內網 HTTPS 入口

先由企業 PKI 把憑證與私鑰安全交付到主機，例如 /secure/transfer/weknora.crt 和 /secure/transfer/weknora.key。以下範例為專用主機；請先填入真實 FQDN 與管理員來源 IP。首次註冊時 Nginx 僅允許此 IP，避免公開註冊視窗被其他人利用。

export WEKNORA_FQDN='kb.corp.example'       # 改成公司真實 FQDN
export WEKNORA_ADMIN_IP='10.20.30.40'      # 改成管理員的固定來源 IP
sudo install -d -m 0700 /etc/nginx/tls
sudo install -m 0644 /secure/transfer/weknora.crt /etc/nginx/tls/weknora.crt
sudo install -m 0600 /secure/transfer/weknora.key /etc/nginx/tls/weknora.key
sudo tee /etc/nginx/sites-available/weknora.conf >/dev/null <<EOF
server {
    listen 443 ssl;
    server_name ${WEKNORA_FQDN};
    ssl_certificate /etc/nginx/tls/weknora.crt;
    ssl_certificate_key /etc/nginx/tls/weknora.key;
    client_max_body_size 50m;
    allow ${WEKNORA_ADMIN_IP};
    deny all;

    location / {
        proxy_pass http://127.0.0.1:8088;
        proxy_http_version 1.1;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
        proxy_set_header X-Forwarded-For \$proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_read_timeout 3600s;
        proxy_buffering off;
    }
}
EOF
sudo ln -s /etc/nginx/sites-available/weknora.conf /etc/nginx/sites-enabled/weknora.conf
# 本指南使用專用新主機；停用 Ubuntu 預設網站，避免多餘的 HTTP 入口。
if [ -L /etc/nginx/sites-enabled/default ]; then
    sudo unlink /etc/nginx/sites-enabled/default
fi
sudo nginx -t
sudo systemctl enable --now nginx
sudo systemctl reload nginx

公司邊界防火牆仍須限制 443 來源；憑證名稱需與員工使用的 FQDN 一致。

內網 HTTPS 只保護員工到前端的連線。若模型服務跨網段，請對該連線使用公司核准的 TLS 或等效網路加密，並把 CA 納入容器信任鏈；不要用跳過憑證驗證解決連線錯誤。

8啟動五個核心服務並做健康檢查

不用 make start-all；它的行為包含額外映像拉取與自動設定兜底。以下明確使用覆寫檔，且禁止啟動時重新拉取或建置。我們未啟用 full、Langfuse、搜尋、MCP、MinIO 等選用 profile。

cd /srv/weknora/source
sudo docker compose -f docker-compose.yml -f compose.internal.yml \
  up -d --no-build --pull never --wait --wait-timeout 600
sudo docker compose -f docker-compose.yml -f compose.internal.yml ps
curl -fsS http://127.0.0.1:8080/health
curl -fsSI http://127.0.0.1:8088/

健康 API 應回傳 {"status":"ok"}，前端應回傳 HTTP 200 或 304。再檢查實際監聽位置：

sudo ss -lntp | grep -E ':443|:8088|:8080'
sudo docker compose -f docker-compose.yml -f compose.internal.yml \
  logs --tail=80 app docreader postgres redis frontend

8088 與 8080 必須只顯示 127.0.0.1；443 由 Nginx 監聽。日誌中若看到密碼、文件或提示詞，應立即調整記錄／遮罩與存取權限。Nginx 憑證可從管理員電腦以瀏覽器開啟 https://kb.corp.example 驗證。

過關條件：五個核心容器 running／healthy、health API 正常、外部無法直接連 8080／8088／資料庫埠。

9建立首位系統管理員，再關閉公開註冊

WeKnora 沒有預設帳號。請先從允許的管理員 IP 開啟 HTTPS 網址，使用正式管理員信箱註冊。密碼依已啟用的複雜度規則設定，長度 8–32 字元。此帳號首先是個人工作空間 Owner，尚非全域系統管理員。

註冊完成後，在部署主機執行以下命令。把信箱改為剛才註冊的信箱；程式會設定首次管理員引導、關閉公開註冊與一般使用者自行建空間，然後重建 app 容器。引導只會提升已存在帳號，且僅在系統尚無任何系統管理員時生效。

cd /srv/weknora/source
export WEKNORA_ADMIN_EMAIL='admin@corp.example'  # 改成剛註冊的信箱
python3 - <<'PY'
from pathlib import Path
import os, re
p=Path('.env')
text=p.read_text(encoding='utf-8')
email=os.environ['WEKNORA_ADMIN_EMAIL'].strip()
if '@' not in email or email.endswith('.example'):
    raise SystemExit('請填寫真實且已註冊的管理員信箱')
for key,value in {
    'WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL': email,
    'DISABLE_REGISTRATION': 'true',
    'WEKNORA_TENANT_SELF_SERVICE_CREATION_ENABLED': 'false',
}.items():
    text,n=re.subn(rf'(?m)^{re.escape(key)}=.*$',lambda _: f'{key}={value}',text)
    if not n: text += f'\n{key}={value}\n'
p.write_text(text,encoding='utf-8')
p.chmod(0o600)
print('管理員引導與註冊限制已寫入 .env')
PY
sudo docker compose -f docker-compose.yml -f compose.internal.yml \
  up -d --no-build --pull never app frontend
sudo docker compose -f docker-compose.yml -f compose.internal.yml \
  logs --tail=60 app

重新登入後，確認「設定」內出現全域系統設定／平台管理項目，並確認註冊頁籤消失。DISABLE_REGISTRATION=true 會在啟動時將註冊模式設為 invite_only；若資料庫中已有系統設定覆蓋，請在管理介面再次確認實際值。後續由系統管理員建立使用者或發送邀請。

確認管理員權限及註冊關閉後，將 /etc/nginx/sites-available/weknora.conf 中的 allow ...; 與 deny all; 兩行移除，執行 sudo nginx -t && sudo systemctl reload nginx，再依企業 ACL 放行員工網段。若公司只允許特定員工網段，也可將這兩行改成對應的 allow 清單與最後的 deny all。

過關條件：首位帳號具有系統管理權限、一般員工不能自註冊、HTTPS 僅對核准的員工網段開放。

10設定內部模型並驗證第一個知識庫

先從 app 容器測試模型主機可達；若模型在宿主機，容器內的 localhost 不是宿主機，應使用可路由的模型服務名稱。為避免文件與問題送到公有雲，模型設定只填公司核准的內網端點與憑證。

cd /srv/weknora/source
sudo docker compose -f docker-compose.yml -f compose.internal.yml \
  exec -T app sh -c 'curl -fsS --max-time 10 "$OLLAMA_BASE_URL/api/tags"'

在 Web UI 的「設定 → 模型」新增兩個模型：對話模型與向量模型（Embedding），來源選 Ollama，填入已由模型平台安裝的實際模型名稱和內網 URL，按「測試連線」後儲存。不要憑空填入模型名；以 /api/tags 回傳清單及模型平台版本為準。若內部服務是 OpenAI 相容 API，改選「自訂（OpenAI 相容接口）」並填公司端點、模型 ID、API Key。

接著到「知識庫」建立一個測試用 document 類型知識庫，在初始化精靈選剛新增的對話與向量模型。先上傳一份不含機密的小型 PDF 或 Markdown；等狀態到 completed，發問並開啟答案引用，確認可回到原文。更換向量模型後必須重建索引，不能直接沿用舊向量。

過關條件：兩種模型測試成功，測試文件完成解析，問答可顯示並開啟引用。

11正式匯入公司文件前的安全封鎖

檢查具體做法與驗收
主機與容器出站建置結束後由網路團隊套用出口 ACL：只允許核准內部模型、內部 DNS、更新鏡像／備份目的地等必要流量。從 app 與 docreader 容器測試外網連線應失敗；另確認模型端點仍可達。不能只靠 SSRF_DNS_WHITELIST_ONLY 或 ufw。
文件解析知識庫解析引擎選本地 Docreader／Anydoc；不要填 WeKnoraCloud、MinerU Cloud、PaddleOCR 雲端憑證。先以測試文件確認解析走內部服務。
模型與追蹤所有 chat／embedding／VLM／ASR 端點逐項審核；LANGFUSE_ENABLED=false 且兩個 Langfuse Key 為空；LLM_DEBUG_LOG=false、LOG_LEVEL=warn。
工具與外部資源保持 Docker 沙箱關閉，不掛載 docker.sock；不啟用網頁搜尋、MCP、外部資料來源、IM 或可公開讀取的資源 URL。瀏覽器可能讀取外部圖片／favicon，企業端再用瀏覽器政策或前端修改管制。
權限與發布埠再次驗證 443、8088、8080 綁定與網路 ACL；確認系統註冊已關閉、管理員只有必要人員、空間授權與審計正常。
映像／相依套件保留映像 digest、漏洞掃描報告與 SBOM；檢查 Dockerfile 建置時取得的第三方來源。正式機從核准內部 registry 取得同一 digest 的映像較佳。

可做一個代表性出站測試，但它不是完整網路證明：

sudo docker compose -f docker-compose.yml -f compose.internal.yml \
  exec -T app sh -c 'curl -fsSI --max-time 5 https://example.com/'
# 預期失敗；接著再次測試內部模型 URL 應成功。
只有完成上述控制、企業正式資安審查與實際網路封包驗證，才匯入機密文件。這份安裝指南不能證明映像或依賴絕對沒有資料外傳行為；前份資安報告列有需修補或持續監測的條件性出口。

12備份、維護與升級

備份基線

至少備份 ParadeDB 資料庫、data-files 卷與原始碼／部署設定，並把 .env 的所有金鑰存放到公司加密秘密管理系統。備份含公司文件與查詢紀錄，須加密、限制讀取者並定期還原演練。Redis 在本 Compose 沒有持久化 volume，備份前應停止新寫入並等非同步佇列完成。

cd /srv/weknora/source
umask 077
BACKUP_DIR="/srv/weknora-backups/$(date +%F-%H%M%S)"
sudo install -d -m 0700 -o "$USER" -g "$USER" "$BACKUP_DIR"
# 先由管理介面確認文件解析佇列已清空，暫停使用者上傳與寫入。
sudo docker compose -f docker-compose.yml -f compose.internal.yml \
  exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' \
  > "$BACKUP_DIR/postgres.dump"
sudo docker cp WeKnora-app:/data/files "$BACKUP_DIR/files"
cp config/config.yaml compose.internal.yml "$BACKUP_DIR/"
sha256sum "$BACKUP_DIR/postgres.dump" > "$BACKUP_DIR/SHA256SUMS"
# 再用公司核准的加密備份系統把整批資料移至異地。

若備份時仍有背景任務寫入，資料庫與檔案卷可能時間點不一致；正式作業請安排維護窗、停止新寫入、等佇列歸零，並在測試環境演練還原。docker compose down 會停止服務並保留命名卷；不要使用 down -v，它會刪除資料卷。

日常維護與升級

每次升級都先審查新 commit、相依套件、資料庫遷移與映像，建立可還原的備份。重新以新 commit 建置三個映像，改成新的內部標籤，更新 .env 中 WEKNORA_VERSION，重新執行步驟 5 的 Compose 埠驗證，再用 up -d --no-build --pull never --wait 更新。APP 啟動可能自動執行資料庫遷移；若需回復，應以升級前的資料庫與檔案備份在隔離環境演練，不能只把映像標籤改回舊版。

診斷命令：

cd /srv/weknora/source
sudo docker compose -f docker-compose.yml -f compose.internal.yml ps
sudo docker compose -f docker-compose.yml -f compose.internal.yml logs --tail=100 app
sudo docker compose -f docker-compose.yml -f compose.internal.yml logs --tail=100 docreader
sudo docker compose -f docker-compose.yml -f compose.internal.yml down  # 保留資料卷；維護停機用

附錄 A：沒有 GPU 時，如何在同機架設對話模型

主流程採用「已有內部 Ollama 端點」作為前提。若目前沒有 GPU，也沒有內部模型服務，可先用同一台主機的 CPU 做少量、非機密文件驗證。下方示範的對話模型是阿里巴巴 Qwen 的 qwen3:4b-instruct（約 2.5 GB），向量模型是北京智源 BAAI 的 bge-m3（約 1.2 GB、1024 維）；兩者均屬中國來源模型，須先通過公司的模型來源及授權審查。這是功能驗證組合，並非已證實足以處理大量公司文件的正式容量。原本 4 vCPU／8 GB 的 WeKnora 主機規格不含模型；同機 CPU 試跑可先以 8 vCPU／32 GB RAM 與足量 SSD 為起點，實際耗時與記憶體須量測。

組合對話 LLM向量模型審查重點
本附錄命令範例阿里巴巴 qwen3:4b-instruct，約 2.5 GBBAAI bge-m3，約 1.2 GB、1024 維確認 Qwen 模型頁的 Apache 2.0 與 BGE-M3 原始模型頁的 MIT 授權，並核對實際匯入版本。
非中國來源替代Google gemma3:4b，約 3.3 GBGoogle embeddinggemma，約 622 MB、768 維兩者受 Gemma 使用條款約束，應交法務確認；也須測試正體中文檢索與抽取品質。

GPU 顯示記憶體如何抓

以下是以本附錄 OLLAMA_CONTEXT_LENGTH=8192、OLLAMA_NUM_PARALLEL=1、Q4 量化對話模型及一個向量模型估算的規劃值，不是廠商保證的最低規格。Qwen3 官方模型清單列出 4B 約 2.5 GB、14B Q4 約 9.3 GB；BGE-M3 約 1.2 GB。GPU 還須容納上下文 KV cache、運行框架與其他負載；Ollama FAQ指出並行數與上下文長度會增加記憶體需求。

可用 VRAM建議用途判斷
8 GBQwen3 4B + BGE-M3，單人、小量文件驗證實務上的 GPU 試跑下限；須用 ollama ps 確認模型是否全載入 GPU，避免部分落在 CPU。
12–16 GBQwen3 4B + BGE-M3，較穩定的小型內部試用若現在才採購，建議至少選 16 GB；能否承受多人同時查詢仍須壓力測試。
24 GB 起評估 Qwen3 14B Q4 + BGE-M3 與圖譜抽取保留較大模型及上下文餘裕；正式容量依文件片段數、延遲與同時使用人數量測。

只有 8 GB 系統 RAM 不能替代 8 GB GPU VRAM；若完全沒有 GPU，沿用本附錄的 CPU 試跑方案。模型從 GPU 溢出至 RAM 可能仍能執行，但回應速度通常會下降。部署後執行 sudo docker compose -f docker-compose.yml -f compose.internal.yml exec -T ollama ollama ps，查看 PROCESSOR 是否為 100% GPU。

下載前審查關卡：將模型供應者、精確 tag 與 digest、模型檔／授權、下載網域、用途和內網保存位置登錄在公司核准清單；在隔離建置區下載並掃描映像與模型檔，保留雜湊與審查紀錄，再匯入內部 registry／模型庫。若尚未核准，先完成 A1、A2 的本地設定，暫停 A3 的下載。無論選哪個模型，模型來源國不直接等於資料外洩；真正控制點是容器出站 ACL、無公開連接埠、停用雲端功能，以及日誌和備份的權限。

A1. 指向同一 Compose 網路中的 Ollama

若尚未建立 .env，在主流程步驟 4 前改用 export WEKNORA_MODEL_URL='http://ollama:11434'，然後照步驟 4 執行一次性的金鑰產生程序。若 .env 已存在，不要重跑金鑰程序；用下列命令只調整模型端點與白名單，保留原密碼及其他已核准主機：

cd /srv/weknora/source
python3 - <<'PY'
from pathlib import Path
import re
p=Path('.env')
if not p.exists(): raise SystemExit('找不到 .env；先完成主流程步驟 4')
s=p.read_text(encoding='utf-8')
def setv(k,v):
    global s
    s,n=re.subn(rf'(?m)^{re.escape(k)}=.*$',lambda _: f'{k}={v}',s)
    if not n: s += f'\n{k}={v}\n'
m=re.search(r'(?m)^SSRF_WHITELIST=(.*)$',s)
hosts=[h.strip() for h in m.group(1).split(',') if h.strip()] if m else []
if 'ollama' not in hosts: hosts.append('ollama')
setv('OLLAMA_BASE_URL','http://ollama:11434')
setv('SSRF_WHITELIST',','.join(hosts))
p.write_text(s,encoding='utf-8'); p.chmod(0o600)
print('模型端點已改為內部 Ollama；原金鑰未更動')
PY

cd /srv/weknora/source
cat >> compose.internal.yml <<'YAML'

A4. 在 WeKnora 設定模型

「設定 → 模型」新增來源為 Ollama 的對話模型，名稱填 qwen3:4b-instruct；再新增來源為 Ollama 的向量模型，名稱填 bge-m3，若須填維度則為 1024。兩者共用 http://ollama:11434。各自按「測試連線」後儲存，知識庫初始化時選用兩個模型。先上傳一份小型非機密文件測試問答與引用。

若審查改採 Google 組合，A3 的兩個 ollama pull 分別改成 gemma3:4b 與 embeddinggemma，對話試跑命令的模型名也改為 gemma3:4b；A4 的 UI 名稱分別填入這兩個 tag，向量維度填 768。官方模型頁要求 Ollama 0.11.10 以上，本附錄採用的 0.34.1 符合版本要求。對話與向量模型可分別選擇公司核准的供應者，但中途更換既有知識庫的向量模型須重建索引並重跑文件向量化。

WeKnora 圖譜抽取對每個文件片段都會呼叫對話 LLM；CPU 版 4B 只適合驗證流程。若佇列累積、單份文件耗時過長，或實體與關係抽取錯誤率偏高，應改用公司既有 GPU 模型服務或增設 GPU，並以人工標註文件評估品質。模型檔案大小不等於運行時 RAM／VRAM 用量。

A5. 若要啟用真正的知識圖譜

主流程不啟用 Neo4j。圖譜功能除了對話 LLM，還要在 .env 設定 NEO4J_ENABLE=true 與強密碼。以下腳本會保留已設定的非預設密碼；重跑不會輪替：

cd /srv/weknora/source
python3 - <<'PY'
from pathlib import Path
import re,secrets
p=Path('.env'); s=p.read_text(encoding='utf-8')
def setv(k,v):
    global s
    s,n=re.subn(rf'(?m)^{re.escape(k)}=.*$',lambda _: f'{k}={v}',s)
    if not n: s += f'\n{k}={v}\n'
m=re.search(r'(?m)^NEO4J_PASSWORD=(.*)$',s)
password=m.group(1) if m else ''
if not password or password=='password': password=secrets.token_hex(24)
setv('NEO4J_PASSWORD',password)
setv('NEO4J_ENABLE','true')
p.write_text(s,encoding='utf-8'); p.chmod(0o600)
print('Neo4j 已設定；請將密碼納入公司秘密管理與備份')
PY
sudo docker compose -f docker-compose.yml -f compose.internal.yml \
  --profile neo4j pull neo4j
sudo docker compose -f docker-compose.yml -f compose.internal.yml \
  --profile neo4j up -d --no-build --pull never --wait --wait-timeout 600

不可沿用預設的 neo4j/password；上述覆寫檔已把 Neo4j 的 7474／7687 主機發布埠移除。最後仍需在目標知識庫啟用圖譜抽取並設定實體、關係類型與示例；全域和知識庫兩級開關都要成立。只用一份小型非機密文件測試，等待非同步圖譜工作完成，並核對抽出的實體與關係。詳見專案圖譜文件。啟用後要將 Neo4j 資料與 Ollama 模型卷納入備份與還原演練。

純 CPU 驗收只用少量文件。A2 的 Compose 範例沒有啟用 GPU 直通；安裝 GPU 後須依NVIDIA Container Toolkit與Docker Compose GPU 文件為 ollama 服務加入 GPU 裝置保留，並用 ollama ps 驗證，才可套用上方 VRAM 規劃。之後再評估較大的 qwen3:14b；硬體容量、延遲與正體中文圖譜抽取品質均需實測，不能只根據模型參數量推定。
