開始之前

完成這份手冊後,你會有一個在本機執行的 Knowledge Hub:上傳文件,由你接上的 AI 模型回答問題,並附上原文出處. 所有資料都存在你電腦上的 Docker volume 裡.

  • 選擇你的系統左側 (手機在上方) 的 Windows, macOS, Linux 會切換整頁的指令.
  • 標記完成每一步右上角的 "完成" 會記錄進度,只存在你的瀏覽器.
  • 一次一步開啟 "一次顯示一個步驟",頁面只留目前的步驟,用底部按鈕前後切換.
  • 複製指令每個指令區塊都有複製按鈕. # 開頭的是註解,一起貼上執行也沒關係.
對應版本

本手冊依據 feature/clean 分支 (v0.8.2) 的 docker-compose.yml, .env.example 與 docker/ 內的 Dockerfile 撰寫. 這個分支移除了中國營運的服務整合,介面語言只有英文,日文,韓文與俄文,沒有中文介面.

會啟動哪些東西

預設設定會啟動 5 個容器. 其中 3 個映像在你的電腦上從原始碼建置,2 個從 Docker Hub 下載. 只有 frontend 和 app 對外開放連接埠,資料庫, Redis 和 docreader 只在 Docker 內部網路 knowledge-hub-network 裡互相連線.

資料存在 3 個 volume: postgres-data (資料庫), data-files (上傳的原始檔), docreader-tmp (解析時的暫存圖片). 刪除容器不會刪到 volume,只有 docker compose down -v 會.

啟動順序: 為什麼網頁要等一兩分鐘

容器之間有相依關係. app 要等 postgres 和 docreader 的健康檢查都通過才會建立,frontend 又要等 app 通過. 健康檢查每 30 秒執行一次,所以每一層至少要等大約 30 秒. 按下播放看整個過程,也可以直接拖曳時間軸.

安裝步驟 · 共 10 步

01

約 5 分鐘

確認系統需求

這個安裝方式會在本機建置 3 個映像. 前端建置時 Node.js 的記憶體上限設為 4 GB,app 映像還要編譯 Go 與 Rust. 資源不足最常見的症狀,就是建置到一半被系統強制中止.

項目最低建議
分配給 Docker 的記憶體8 GB12 GB 以上
CPU4 核心8 核心以上
可用磁碟空間30 GB50 GB 以上
CPU 架構x86_64 (amd64) 或 arm64,包含 Apple Silicon
作業系統Windows 10/11 (搭配 WSL 2), macOS, 主流 Linux 發行版

表格中的數字是依建置內容估計的建議值,不是官方測試過的最低規格.

網路

第一次建置要下載大量套件,連線對象包含 Docker Hub, GitHub, sh.rustup.rs, proxy.golang.org, npm registry, PyPI 與 Debian 套件庫. 公司網路如果有 Proxy 或防火牆,請先在 Docker 裡設定 Proxy (Docker Desktop: Settings → Resources → Proxies),否則建置會在中途逾時.

提示

實體記憶體 16 GB 以上的電腦,通常可以分 8 GB 以上給 Docker. 如果整台電腦只有 8 GB,建置時請關掉瀏覽器以外的大型程式,並參考第 6 步的 WITH_ANYDOC=0 與逐一建置的做法.

02

約 10 到 20 分鐘

安裝 Docker 並分配資源

你需要 Docker Engine 與 Compose v2,指令是 docker compose (中間是空格). 舊版有連字號的 docker-compose (v1) 不建議使用.

  1. 確認已啟用虛擬化: 工作管理員 → 效能 → CPU,右下角的 "虛擬化" 要顯示 "已啟用". 沒有的話要到 BIOS/UEFI 開啟.
  2. 以系統管理員身分開啟 PowerShell,執行 wsl --install,完成後重新開機.
  3. 安裝 Docker Desktop for Windows,安裝時保留 "Use WSL 2 instead of Hyper-V".
  4. 設定 WSL 能用的記憶體. 使用 WSL 2 時,Docker Desktop 的記憶體上限由 WSL 決定,預設是實體記憶體的一半. 在 %UserProfile%\.wslconfig 寫入下面內容 (依你的電腦調整),再執行 wsl --shutdown 並重新開啟 Docker Desktop.
%UserProfile%\.wslconfig
[wsl2]
memory=12GB
processors=8
  1. 安裝 Docker Desktop for Mac,依晶片選 Apple Silicon 或 Intel 版本.
  2. 開啟 Docker Desktop → Settings → Resources,把 Memory 調到 8 GB 以上,Disk usage limit 至少留 50 GB,按 Apply & restart.
  1. 依 Docker 官方文件 安裝 Docker Engine 與 docker-compose-plugin. 不建議使用發行版內建的舊套件 (例如 docker.io).
  2. 啟動服務,把自己加入 docker 群組,然後登出再登入:
Terminal (bash)
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
注意

docker 群組等同 root 權限,只加入你信任的帳號. Rootless Docker 或 Podman 不能直接使用 80 埠,請在第 4 步把 FRONTEND_PORT 改成 1024 以上,例如 8000. 本手冊以 Docker 為準,Podman 沒有完整驗證.

驗證安裝

終端機 (任何系統)
docker version
docker compose version
docker run --rm hello-world
成功

docker version 同時有 Client 與 Server 兩段, docker compose version 顯示 v2 以上的版本, hello-world 印出 "Hello from Docker!".

注意

如果只有 Client 沒有 Server,或出現 "Cannot connect to the Docker daemon",代表 Docker 沒有在執行. Windows 與 macOS 請先開啟 Docker Desktop,等左下角顯示 Engine running 再試一次.

04

約 5 分鐘 · 最重要的一步

設定 .env

docker-compose.yml 從專案根目錄的 .env 讀取設定,app 容器也會直接載入整個檔案. 找不到 .env 時 Compose 會直接報錯. 你可以用下面的產生器做出完整的 .env,也可以複製範本後手動修改.

先讀這 5 條
  1. 資料庫的帳號,密碼與名稱只在第一次啟動時生效. postgres 第一次啟動時用 DB_USER, DB_PASSWORD, DB_NAME 建立資料庫並寫進 volume. 之後再改 .env,資料庫不會跟著變,app 就連不上.
  2. DB_NAME 不能有空格. 健康檢查 pg_isready -d ${DB_NAME} 和 app 的連線字串都沒有加引號,名稱有空格時 postgres 會一直 unhealthy. 請用 knowledge_hub 這種寫法.
  3. 密碼只用英文字母和數字. $ 會被 Compose 當成變數,空白後面的 # 會被當成註解,空白和引號也可能讓值被截斷.
  4. SYSTEM_AES_KEY 必須剛好 32 個字元,設定後不要再改. 你在介面輸入的模型 API key 會用它加密. 長度不對時加密會被停用;換掉它之後,已經存下的 API key 全部無法解密.
  5. JWT_SECRET 要設定固定值. 留空時 app 每次啟動都會隨機產生一個,重啟後所有人都會被登出.

密碼與金鑰由瀏覽器的 crypto.getRandomValues 在本機產生,不會傳送到任何地方. 產生器以此分支的 .env.example 為範本,只修改下列項目,其餘維持預設.

變數建議值說明

產生隨機金鑰:

PowerShell 7
# 32 字元,給 SYSTEM_AES_KEY
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(16)).ToLower()
# 64 字元,給 JWT_SECRET 與 SYSTEM_SIGNING_KEY
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)).ToLower()
Terminal
openssl rand -hex 16   # 32 字元,給 SYSTEM_AES_KEY
openssl rand -hex 32   # 64 字元,給 JWT_SECRET 與 SYSTEM_SIGNING_KEY

保管

.env 已經被 .gitignore 排除. 不要 commit,也不要貼到聊天室或 issue. 請另外備份一份,尤其是 SYSTEM_AES_KEY: 遺失它就得重新輸入所有模型的 API key.

05

約 2 分鐘

檢查連接埠

預設會用到本機的 80 (網頁) 與 8080 (API). 如果已經被其他程式占用,啟動時會出現 "port is already allocated" 或 "ports are not available".

PowerShell
Get-NetTCPConnection -State Listen -LocalPort 80,8080 -ErrorAction SilentlyContinue |
  Select-Object LocalPort, OwningProcess, @{n='Process';e={(Get-Process -Id $_.OwningProcess).ProcessName}}
Terminal (zsh)
lsof -nP -iTCP:80 -sTCP:LISTEN
lsof -nP -iTCP:8080 -sTCP:LISTEN
Terminal (bash)
sudo ss -ltnp | grep -E ':(80|8080)\s'
成功

沒有任何輸出,代表兩個埠都可以用.

被占用時

不需要關掉對方,在 .env 改 FRONTEND_PORT (例如 8000) 或 APP_PORT (例如 18080) 就好,之後網頁改開 http://localhost:8000.

Windows 上 80 埠顯示由 PID 4 (System) 占用,通常是 IIS 或其他使用 http.sys 的服務.

常見會占用 8080 的程式: 其他開發伺服器,以及 llama.cpp server (預設也是 8080).

06

第一次約數十分鐘

建置並啟動

在專案資料夾執行下面的指令. Compose 會先建置 frontend, app, docreader 三個映像,下載 postgres 與 redis,再依相依順序啟動容器. -d 代表啟動完成後回到命令列,容器留在背景執行.

終端機 (任何系統)
docker compose up -d --build
結尾的範例輸出
 ✔ Container knowledge-hub-redis      Started
 ✔ Container knowledge-hub-postgres   Healthy
 ✔ Container knowledge-hub-docreader  Healthy
 ✔ Container knowledge-hub-app        Healthy
 ✔ Container knowledge-hub-frontend   Started

建置期間會看到什麼

  • 大量的下載與編譯訊息. app 映像要安裝 Rust 並編譯 anydoc 文件引擎,通常最久.
  • 建置結束後,畫面會停在 Waiting 大約 1 到 2 分鐘. 這是在等健康檢查,不是當機,可以回頭看 啟動流程動畫.
注意

建置途中按 Ctrl+C 會中止,但不會弄壞任何東西. 再執行一次同樣的指令,已完成的部分會從快取接續. 筆電請接上電源,並暫時關閉睡眠.

記憶體不夠或想加快建置

方法一: 在 .env 加入 WITH_ANYDOC=0,跳過 Rust 工具鏈與 anydoc 引擎. 代價是 Office 文件改由 docreader 解析.

方法二: 一次只建置一個映像,降低記憶體尖峰:

終端機 (任何系統)
docker compose build frontend
docker compose build docreader
docker compose build app
docker compose up -d
(選用) 讓系統資訊頁顯示前端的 commit

沒設定時系統資訊頁會顯示 unknown,不影響功能. 需要時在同一個終端機,於 docker compose up 之前執行:

PowerShell
$env:VITE_FRONTEND_COMMIT = (git rev-parse --short HEAD)
Terminal
export VITE_FRONTEND_COMMIT=$(git rev-parse --short HEAD)
說明

BrowserSkill 瀏覽器整合預設不會建置 (WITH_BROWSERSKILL=0),不影響一般功能. 需要時請參考 docker/Dockerfile.app 開頭的說明.

不要這樣啟動

scripts/start_all.sh 不加參數時,會嘗試在本機安裝並啟動 Ollama (Linux 上會下載並執行遠端安裝腳本). 真的要用請加上 --docker. make docker-run 使用舊版的 docker-compose 指令,也不建議.

出現錯誤訊息時,把訊息的關鍵字貼到 疑難排解 的搜尋框.

08

約 5 分鐘

建立帳號與系統管理員

  1. 在登入頁找到 "New to Knowledge Hub?",點 Create Account.
  2. 填入 Username (2 到 20 個字元), Email 與 Password (8 到 32 個字元).
  3. 看到 "Registration successful. Please sign in" 之後,用 Email 與密碼登入.
  4. 如果出現 "Choose your workspace",選 Create workspace 建立自己的工作區.

讓帳號成為系統管理員

注意

第一個註冊的帳號不會自動成為系統管理員. 平台層級的設定 (例如全域系統設定) 只有系統管理員能調整.

  1. 確認 .env 裡有 WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL=你註冊用的 Email. 產生器有這個欄位,沒填的話現在手動加上.
  2. 重建 app 容器,讓它在啟動時執行升級:
終端機 (任何系統)
docker compose up -d --force-recreate --no-deps app
PowerShell
docker compose logs app | Select-String "bootstrap"
Terminal
docker compose logs app | grep bootstrap
成功

log 出現 [bootstrap] promoted user ... to system admin. 登出再登入後,就能看到系統管理功能.

說明

這個設定只在系統裡還沒有任何系統管理員時生效. 留在 .env 裡不會重複授權,也不會覆蓋之後在介面上調整的權限.

(建議) 關閉公開註冊

只有自己使用可以跳過. 如果這台電腦在區網上能被別人連到,建立好需要的帳號後,在 .env 設定 DISABLE_REGISTRATION=true,再執行 docker compose up -d.

注意

系統管理員在介面上儲存過的系統設定會寫進資料庫,優先權高於 .env. 以後改 .env 沒有效果時,先檢查介面上的設定.

選項 B: 本機 Ollama

在主機 (不是容器裡) 安裝 Ollama,下載要用的模型. 下面的模型名稱只是範例:

終端機 (任何系統)
ollama pull nomic-embed-text
ollama pull llama3.1:8b

app 透過 OLLAMA_BASE_URL 連到主機上的 Ollama,預設是 http://host.docker.internal:11434.

說明

Docker Desktop 會把 host.docker.internal 轉到你的主機,Ollama 維持預設設定即可.

Linux 必做

Linux 上的 Ollama 預設只接受 127.0.0.1 的連線,容器連不到. 要讓它監聽所有介面:

1. 開啟 systemd 覆寫設定
sudo systemctl edit ollama
2. 在編輯器中加入這兩行並存檔
[Service]
Environment="OLLAMA_HOST=0.0.0.0"
3. 重新載入並重啟
sudo systemctl daemon-reload
sudo systemctl restart ollama
安全

OLLAMA_HOST=0.0.0.0 會讓同一個網路的其他電腦也能使用你的 Ollama. 請用防火牆把 11434 埠限制為只允許本機與 Docker 網段.

從 app 容器裡確認連得到 Ollama:

終端機 (任何系統)
docker compose exec app curl -s http://host.docker.internal:11434/api/tags
成功

選項 C: 本機的 OpenAI 相容服務

LM Studio, vLLM, llama.cpp 這類服務,Base URL 要寫成 http://host.docker.internal:埠號/v1. 不能寫 localhost: 在容器裡,localhost 指的是 app 容器自己.

SSRF 防護

為了防止 SSRF,app 預設會拒絕 host.docker.internal, localhost 與內網位址,新增模型時會出現 SSRF 驗證錯誤. 請在 .env 加入 SSRF_WHITELIST=host.docker.internal (內網主機可以寫 IP 或 CIDR,用逗號分隔),再執行 docker compose up -d. 只加入你信任的主機. 產生器勾選對應選項就會自動加入.

注意

疑難排解

把錯誤訊息的關鍵字貼進搜尋框,例如 port, unhealthy, SSRF, 502. 看 log 的通用指令是 docker compose logs --tail 200 服務名稱.

找不到 .envenv file ... .env not found

原因還沒有建立 .env. app 服務使用 env_file: .env,這個檔案必須存在.

解法回到 第 4 步 建立 .env,確認它和 docker-compose.yml 在同一層資料夾.

建置 app 時要求 BrowserSkill 原始碼Set BROWSERSKILL_SOURCE_DIR to a reviewed local BrowserSkill source checkout

原因你的程式碼是舊版,當時 BrowserSkill 還是必要的建置步驟;或是 .env 裡設定了 WITH_BROWSERSKILL=1.

解法執行 git pull 更新到最新的 feature/clean,並確認 WITH_BROWSERSKILL 沒有設成 1,再重新建置.

建置到一半被中止,記憶體不足JavaScript heap out of memory / exit code: 137 / Killed

原因分配給 Docker 的記憶體不夠,前端或 Rust 編譯時被系統中止.

解法依 第 2 步 提高 Docker 的記憶體,或用第 6 步的 WITH_ANYDOC=0 與逐一建置.

下載套件逾時或失敗TLS handshake timeout / i/o timeout / Could not resolve host

原因網路不穩,或公司 Proxy 與防火牆擋住了 Docker Hub, GitHub, npm, PyPI 等來源.

解法直接重跑 docker compose up -d --build,已完成的部分會用快取. 公司網路請先在 Docker 設定 Proxy.

BuildKit 相關錯誤the --mount option requires BuildKit

原因Docker 版本太舊,或關閉了 BuildKit. Dockerfile 使用了 RUN --mount.

解法更新 Docker,並確認沒有設定 DOCKER_BUILDKIT=0.

連接埠被占用port is already allocated / ports are not available

原因80 或 8080 已經有其他程式在用.

解法在 .env 改 FRONTEND_PORT 或 APP_PORT,再執行 docker compose up -d. 找出占用程式的方法見 第 5 步.

容器名稱衝突Conflict. The container name "/knowledge-hub-app" is already in use

原因compose 檔固定了容器名稱,同一台電腦只能跑一份. 通常是另一個資料夾的副本還在執行.

解法到原本的資料夾執行 docker compose down. 確定不需要時,也可以用 docker rm -f knowledge-hub-app 移除單一容器.

postgres 一直 unhealthydependency failed to start: container knowledge-hub-postgres is unhealthy

原因最常見的是 DB_NAME 有空格,健康檢查的 pg_isready 會回報 "too many command-line arguments". 舊版範本的 DB_NAME=Knowledge Hub 就會發生.

解法把 DB_NAME 改成 knowledge_hub. 如果是全新安裝,還沒有任何資料,執行 docker compose down -v 清掉用舊名稱建立的資料庫,再 docker compose up -d.

資料庫密碼錯誤password authentication failed for user

原因第一次啟動之後修改了 DB_PASSWORD. 資料庫仍然使用第一次設定的密碼.

解法把 .env 改回原本的密碼. 如果要換新密碼,先進入 psql:

終端機 (任何系統)
docker compose exec postgres sh -c 'psql -U $POSTGRES_USER -d $POSTGRES_DB'

執行 ALTER USER postgres WITH PASSWORD '新密碼'; (帳號依你的 DB_USER),輸入 \q 離開,把新密碼寫進 .env 後執行 docker compose up -d. 全新安裝沒有資料時,也可以 docker compose down -v 重來.

redis 不斷重啟wrong number of arguments / Restarting

原因REDIS_PASSWORD 是空的. redis 以 --requirepass ${REDIS_PASSWORD} 啟動,沒有值就會失敗.

解法在 .env 設定 REDIS_PASSWORD (只用英數字),再執行 docker compose up -d.

app unhealthy 或一直重啟container knowledge-hub-app is unhealthy

原因通常是連不上資料庫或 Redis,或 migration 失敗.

解法執行 docker compose logs --tail 200 app,先看 [startup-env] 區塊確認設定有被讀到,再往下找第一個 error. migration 失敗時不要刪除資料庫,見 日常操作 的更新說明.

網頁顯示 502 Bad Gateway502 Bad Gateway

原因frontend 已經在跑,但 app 還沒準備好或正在重啟.

解法用 docker compose ps 確認 app 是 (healthy),不是的話看 app 的 log.

上傳檔案失敗,檔案太大413 Request Entity Too Large

原因超過 MAX_FILE_SIZE_MB,預設 50 MB. nginx 與 app 都用這個值限制.

解法在 .env 設定更大的 MAX_FILE_SIZE_MB,再執行 docker compose up -d.

每次重啟後所有人都被登出JWT_SECRET=<unset>

原因JWT_SECRET 沒有設定,app 每次啟動都隨機產生新的簽章金鑰.

解法設定固定的 64 字元值,再執行 docker compose up -d. 設定後大家需要重新登入一次.

模型 API key 失效,log 出現解密失敗decrypt failed (SYSTEM_AES_KEY missing/rotated?)

原因SYSTEM_AES_KEY 和當初加密時不同,或長度不是 32.

解法改回原本的金鑰,再執行 docker compose up -d. 如果原本的金鑰遺失,只能在介面重新輸入所有 API key.

金鑰長度錯誤的警告SYSTEM_AES_KEY is set but N bytes long / no usable signing key

原因SYSTEM_AES_KEY 不是剛好 32 字元,這時加密會被停用;或沒有可用的 SYSTEM_SIGNING_KEY.

解法還沒輸入任何 API key 的話,修正 .env 後執行 docker compose up -d. 已經輸入過 API key 的話,請先閱讀上一則.

新增模型時 Base URL 被拒SSRF validation failed

原因app 預設拒絕 host.docker.internal, localhost 與內網位址.

解法在 .env 加入 SSRF_WHITELIST=host.docker.internal 或你的內網 IP, CIDR,再執行 docker compose up -d. 系統管理員若已在介面儲存過相關設定,以介面上的值為準.

Base URL 用 localhost 連不到connection refused

原因在容器裡, localhost 指的是 app 容器自己,不是你的電腦.

解法改用 http://host.docker.internal:埠號,並依上一則加入 SSRF 白名單.

Linux 上連不到 OllamaOllama service unavailable

原因Ollama 預設只監聽 127.0.0.1,Docker 容器連不進去;或防火牆擋住 11434 埠.

解法依 第 9 步 設定 OLLAMA_HOST=0.0.0.0,再用 docker compose exec app curl -s http://host.docker.internal:11434/api/tags 測試.

登入後看不到系統管理功能is_system_admin = false

原因第一個註冊的帳號不會自動成為系統管理員.

解法依 第 8 步 設定 WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL 並重建 app 容器.

修改 .env 沒有生效docker compose restart

原因restart 只重啟既有的容器,不會重新讀取 .env. 另一個可能是系統管理員已在介面上儲存過該設定.

解法改用 docker compose up -d,它會重建設定有變動的容器.

文件一直停在處理中docreader

原因大型或圖片很多的 PDF 需要比較久;也可能是 docreader 出錯或逾時.

解法用 docker compose logs -f docreader app 觀察. 處理時間上限可以用 WEKNORA_DOCUMENT_PROCESS_TIMEOUT 調整,例如 2h.

更換 embedding 模型後搜尋結果變差embedding dimension

原因新舊模型的向量維度與語意空間不同,舊文件的索引還是用舊模型做的.

解法重建受影響知識庫的索引,或換回原本的模型.

app 無法啟動,找不到 entrypointexec ./scripts/docker-entrypoint.sh: no such file or directory

原因.sh 檔被存成 CRLF 換行,常見於 Windows 編輯器.

解法把檔案換行改回 LF (例如 VS Code 右下角的 CRLF 點一下改成 LF),或重新 clone,然後重新建置.

登入 API 回傳 HTML 404POST /api/v1/auth/login 404

原因啟用 searxng 時把 SEARXNG_PORT 設成和 APP_PORT 一樣,請求被 searxng 接走.

解法把 SEARXNG_PORT 改回 8888 或其他空的埠.

log 一直出現 Langfuse 連線錯誤langfuse-web:3000

原因舊版範本帶有 LANGFUSE_PUBLIC_KEY 與 LANGFUSE_SECRET_KEY 的佔位值,只要兩個都有值就會自動啟用追蹤.

解法沒有啟用 langfuse profile 的話,把這兩行註解掉或設定 LANGFUSE_ENABLED=false,再執行 docker compose up -d.

沒有符合的項目. 試試錯誤訊息裡比較短的關鍵字,或看 docker compose logs --tail 200 app 裡第一個 error.

進度與系統選擇只存在你的瀏覽器. 產生器的密碼不會被儲存.
